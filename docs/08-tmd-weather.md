# พยากรณ์กรมอุตุนิยมวิทยา

เพิ่มหน้าพยากรณ์ฝนและลมบน Dashboard และ เพิ่มเติม → การเชื่อมต่อ API ใช้ข้อมูลจริงจาก TMD Weather Forecast API ตามพิกัดอ้างอิงลำห้วยหลัว 16.6971878, 103.7459312 (ไม่ใช่พิกัดสำนักงานหรือจุดเกิดเหตุ) ขอข้อมูลรายชั่วโมง 24 ชั่วโมง โดยแสดงปริมาณฝน mm/ชั่วโมง ความเร็วลมที่ระดับ 10 เมตร m/s ทิศลม และอุณหภูมิ °C

## การตั้งค่า

1. ติดตั้ง schema.sql และ tmd-weather.sql ตามลำดับ
2. เก็บ OAuth Access Token ของกรมอุตุฯ ใน Supabase Edge Functions → Secrets ชื่อ `TMD_API_TOKEN` (รองรับชื่อเดิม `กรมอุตุ token` ด้วย) ไม่เติม Bearer และไม่เก็บ Token ในเว็บ Git หรือ localStorage
3. Deploy ฟังก์ชัน tmd-weather จาก supabase/functions/tmd-weather/index.ts และ forecast.ts

ฟังก์ชันตั้ง verify_jwt=false เพื่อรองรับ publishable API key และตรวจ apikey ด้วย SUPABASE_PUBLISHABLE_KEYS / SUPABASE_ANON_KEY ในโค้ดเอง รองรับเฉพาะ GET สำหรับข้อมูลอากาศสาธารณะหนึ่งพื้นที่ รับ CORS เฉพาะเว็บหน่วยงานและ localhost ที่ใช้ทดสอบ ไม่ให้ caller เปลี่ยน URL พิกัด ชุดข้อมูล หรือระยะพยากรณ์ และไม่มีข้อมูลเหตุ เจ้าหน้าที่ หรือบุคคลอยู่ในคำตอบ

ตาราง external_weather_cache เปิด RLS ไม่มีสิทธิ์อ่าน/เขียนให้ anon หรือ authenticated โดยตั้งใจ Edge Function ใช้ server-only key เท่านั้น จึงไม่ต้องมี policy อนุญาตผู้ใช้เว็บเข้า cache ตรงๆ [รายละเอียด RLS enabled without policy](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)

## การอัปเดตและข้อมูลเก่า

ใช้ฐานข้อมูลพักผลพยากรณ์ร่วมกันอย่างน้อย 15 นาที คำสั่ง claim_tmd_weather_refresh แบบ atomic ป้องกันผู้ใช้หลายคนเรียกกรมอุตุฯ พร้อมกัน หากล้มเหลวรออย่างน้อย 60 วินาทีจึงลองอีกครั้ง การโหลดเกิดเมื่อเปิดหน้าหรือกดอัปเดต และทุก 15 นาทีขณะหน้านั้นเปิดและมองเห็น ไม่มีงานเบื้องหลังส่งแจ้งเตือนอัตโนมัติ

ถ้า Token ไม่พบ หมดอายุ API จำกัดจำนวนเรียกหรือไม่ตอบ ระบบแสดงข้อความจริง หากเคยดึงข้อมูลได้ เก็บข้อมูลเดิมพร้อมวันเวลาและป้ายข้อมูลเก่า หากไม่เคยได้ข้อมูล ไม่แสดงตัวเลขฝน/ลมจำลอง ค่า 0 และไม่มีข้อมูลแยกจากกัน ไม่รับผลพยากรณ์เก่าที่ไม่ครอบคลุมเวลาปัจจุบัน

เก็บผลที่ดึงสำเร็จใน localStorage ของเครื่องเพื่ออ่านแบบออฟไลน์ โดยไม่เก็บ Token ข้อมูลในส่วนนี้เป็นพยากรณ์แบบจำลอง ไม่ใช่เรดาร์ฝน ค่าฝนที่วัดหน้างาน หรือประกาศเตือนภัยจากกรมอุตุฯ

## อ้างอิงและตรวจสอบ

- [คู่มือข้อมูลรายชั่วโมง](https://data.tmd.go.th/nwpapi/doc/apidoc/location/forecast_hourly.html)
- [การสร้าง Token](https://data.tmd.go.th/nwpapi/doc/main/getting_start.html)
- ทดสอบ normalization, ค่า 0/ไม่มีข้อมูล, ผลพยากรณ์หมดอายุ, refresh claim และสิทธิ์ cache ด้วย tests/weather.mjs
- ทดสอบหน้าจอมือถือ แสดง 24 ชั่วโมง ข้อมูลเก่าหลัง API ล้มเหลว และ offline reload ด้วย tests/weather-browser.mjs ข้อมูลจำลองใช้เฉพาะใน tests เท่านั้น
- Build, TypeScript, วงจรเหตุเดิม และ offline draft ต้องผ่านก่อนเผยแพร่

ผลทดสอบเชื่อมต่อจริงวันที่ 8 ต.ค. 2569: Edge Function เรียกได้และปฏิเสธ API key ไม่ถูกต้อง พบ Secret ชื่อเดิม กรมอุตุ token แล้ว แต่การเชื่อมต่อ HTTPS จาก Supabase ไป data.tmd.go.th หลุดระหว่าง TLS handshake (eof) จึงยังไม่มีผลพยากรณ์จริง ไม่แสดงตัวเลขจำลอง ไม่ปิดการตรวจใบรับรองและไม่ส่ง Token ผ่าน HTTP ต้องให้ผู้ให้บริการตรวจการเชื่อมต่อ TLS หรือใช้ HTTPS endpoint ทางการที่เชื่อมได้ จึงจะทดสอบความถูกต้องของ Token และข้อมูลพยากรณ์ได้

หมายเหตุ: ลองบังคับ HTTP/1.1 เพื่อรองรับเซิร์ฟเวอร์เก่า โดยยังตรวจ TLS ตามปกติ ไม่มีการใช้ ignoreCertificateErrors หรือ HTTP สำหรับส่ง Token

# การเชื่อมต่อข้อมูลจริง ปภ. ลำห้วยหลัว

ตั้งค่าบนโปรเจกต์ `zkmaubtpxiptbbqtazfr` แล้ว เว็บมี URL และ publishable key เริ่มต้น จึงไม่ต้องคัดลอกคีย์ด้วยตนเอง ไม่มี service_role key ในเว็บหรือซอร์สโค้ดที่เผยแพร่

หน่วยงาน: ปภ. ตำบลลำห้วยหลัว อำเภอสมเด็จ จังหวัดกาฬสินธุ์ บัญชีผู้ดูแลแรกสร้างใน Supabase Auth และผูกกับ public.users แล้ว ต้องเปิดลิงก์เชิญครั้งเดียวและตั้งรหัสผ่านเองก่อนใช้งาน ลิงก์เชิญไม่ได้เก็บในไฟล์หรือ Git

หลังตั้งรหัสผ่าน ไปที่ **เพิ่มเติม → การตั้งค่า → เปิดข้อมูลหน่วยงานจริง** จากนั้นเพิ่มกำลังพล รถ และอุปกรณ์จริงในหน้าทรัพยากร ก่อนรับแจ้งและมอบหมายงาน ข้อมูลตัวอย่างในเครื่องไม่ถูกนำเข้าฐานข้อมูลจริง

## ฐานข้อมูลและสิทธิ์

ติดตั้ง 23 ตารางพร้อม Foreign Key และเปิด RLS ทุกตาราง ใช้ private schema สำหรับตัวช่วยสิทธิ์ บัญชีที่ยังไม่ยืนยันอีเมลหรือยังไม่มีโปรไฟล์หน่วยงานไม่สามารถใช้สิทธิ์หน่วยงานได้ รูปอยู่ใน bucket incident-photos แบบ private ขนาดไม่เกิน 15 MB และจำกัดชนิดไฟล์ที่รองรับ

คำสั่งสร้างเหตุ เปลี่ยนสถานะ มอบหมายทรัพยากร Checklist และปิดเหตุใช้ RPC ซึ่งตรวจ Auth บทบาท หน่วยงาน และ version พร้อม UUID ป้องกันคำสั่งซ้ำ เก็บ Audit Log และรายงาน snapshot เมื่อปิดเหตุ

เครื่องมือเปิดบัญชีชั่วคราว `drc-admin-bootstrap` ปิดการทำงานแล้ว (ตอบ 410 และบังคับ JWT) ไม่มี endpoint ให้บุคคลอื่นสร้างผู้ดูแลต่อได้

## ผลตรวจ

- Build และ TypeScript ผ่าน
- ทดสอบฐานข้อมูล: วงจรเหตุครบ Checklist การส่งซ้ำ version conflict คืนทรัพยากร รายงาน Audit สิทธิ์ และ soft delete ผ่าน
- ทดสอบเว็บเดสก์ท็อป/มือถือ วงจรเหตุ ภาพ PDF ภาษาไทย และออฟไลน์ผ่าน
- ทดสอบหน้ารับคำเชิญด้วย Auth จำลองผ่าน โดยไม่ได้ใช้ลิงก์เชิญของผู้ดูแลจริง
- ทดสอบ RPC บน PostgreSQL จริงภายใน transaction แล้ว rollback ผ่าน ไม่มีเหตุหรือทรัพยากรทดสอบค้างอยู่ในฐานข้อมูล
- ยืนยัน RLS ทั้ง 23 ตาราง bucket private และบัญชีที่ยังไม่เปิดใช้งานไม่มีสิทธิ์หน่วยงาน
- ถอน default privileges แล้วให้สิทธิ์ตารางอย่างชัดเจน: anonymous ไม่อ่านตารางธุรกิจ และ authenticated ไม่แก้เหตุ/ทรัพยากรโดยข้าม RPC
- แก้คำเตือน index ของ Foreign Key และ Auth RLS initplan แล้ว

## ข้อสังเกตจาก Supabase Advisors

RPC 10 ฟังก์ชันใช้ SECURITY DEFINER โดยตั้งใจเพื่อบันทึกหลายตารางพร้อมกันและบังคับวงจรเหตุ ฟังก์ชันเหล่านี้ตรวจสิทธิ์ในตัว ตั้ง search_path ว่าง และให้เฉพาะ authenticated เรียกได้ ตัวช่วยสิทธิ์อยู่ใน private schema และ trigger audit ไม่ให้เรียกผ่าน API ดู [คำอธิบายคำเตือน SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)

โปรเจกต์ยังปิด Leaked Password Protection หากแพ็กเกจรองรับ ให้เปิดใน Supabase Dashboard → Authentication → Settings → Security ตาม [แนวทางความปลอดภัยรหัสผ่าน](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) ยังไม่ได้เปลี่ยนแพ็กเกจหรือค่าใช้จ่ายของโปรเจกต์

คำเตือน unused index เป็นข้อมูลประกอบจากฐานข้อมูลใหม่ที่ยังไม่มีงานจริง ไม่ควรลบดัชนีสำหรับ Foreign Key เพียงเพราะยังไม่เคยใช้งาน ดู [Unused Index](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)

เว็บยังคงเผยแพร่เฉพาะเจ้าของ Sites เท่านั้น การใช้งานของทีมต้องกำหนดผู้เข้าชมเว็บและสร้างบัญชี Auth พร้อมโปรไฟล์สิทธิ์ของเจ้าหน้าที่แต่ละคน ไม่ใช้บัญชีผู้ดูแลร่วมกัน การส่งแจ้งเตือนและข้อมูลบริการภายนอกยังรอเชื่อม API จริง
